IELTS Speaking Evaluator

A Progressive Web App that lets IELTS evaluators score speaking tests in real time, with a user experience tailored for evaluators. It band-caps and surfaces fluency gaps in real time.

The Problem

Teachers conducting IELTS speaking assessments needed a replicable method to score against IELTS criteria rubric in real time, during class, without relying on paper or complex software. The existing tools were either too heavy, too expensive, or required constant connectivity.

The Constraint

The tool had to run on teachers' personal devices, work reliably on inconsistent connections, and be immediately intuitive to evaluators who are focused on the student, not the interface.

What I Built

A Progressive Web App built in vanilla JavaScript that eases real-time scoring against official IELTS rubrics. The interface surfaces "band-capping alerts"—moments where a student's performance in one criterion (like grammar range) limits their overall band regardless of strengths elsewhere.

  • Core logic in vanilla JS with zero external dependencies
  • Works offline after initial load
  • Clean, distraction-free UI designed for evaluators under time pressure
  • Progressive Web App: installable for browsers, phones, and tablets without app stores

Why This Way

A framework would add weight and dependencies for a problem that is fundamentally about logic and interface clarity. The scoring algorithm is the product; the UI's job is to get out of the way. Vanilla JS keeps the bundle small, the performance predictable, and the maintenance straightforward. A robust reporting dashboard lets instructors evaluate progress for classes and students, and share that feedback.

Teacher Tool · My Daily Driver

Lesson Prepper

One pipeline from raw text to editable PowerPoint. Saves hours per week.

The Problem

Teachers spent hours per lesson manually formatting slides, copying text from PDFs, and adjusting layouts. The existing "digital curriculum" was a patchwork of documents that required constant reformatting.

The Constraint

No budget for proprietary LMS. No IT support. Teachers used whatever was on their laptops—mostly old versions of PowerPoint and MS Word, and free Google accounts. The solution had to be affordable, offline-capable, and output something teachers already knew how to use.

What I Built

A pipeline that evolved from a Google Gem + Python script into one tool: paste text → get structured lesson plan → customize slide layout → export editable PowerPoint. The AI handles the structure; the teacher handles the pedagogy.

  • Text ingestion—pasted from anywhere
  • AI-structured lesson plans with objectives, activities, and assessments
  • Customizable slide templates matching school branding
  • Direct, customizable and editable PowerPoint export—no starting from scratch

Why This Way

Teachers need efficiency. They need PowerPoint files that aren't locked down and un-editable—like the slides Notebook LM creates. By exporting to a format they already own, I removed the adoption barrier entirely. The AI is a convenience layer; the PowerPoint is the deliverable.

Curriculum Design

Web Dev Fundamentals

A full 35 week term syllabus teaching HTML5, CSS3, and JavaScript to secondary students or adult learners. Project-based, no prior experience needed.

The Problem

Many coding courses start with tools. I start with thinking. Once you understand why code behaves the way it does, any tool becomes easier to use. Logic and causality first. Tools second. Students who understand the 'why' adapt faster.

What I Built

A scaffolded curriculum using foundational web methodology. HTML and CSS taught like they matter just as much as JavaScript. The methods behind fundamentals are ingrained. Context is provided alongside syntax, thinking is required. Modules progress from basic index.html and styles.css to DOM manipulation, all in vanilla JS, with the rationale for why and when to use advanced tools baked in.

Designed for secondary students or adult learners with no prior experience.

Why This Way

Frameworks abstract away the very concepts I want students to see. When a student writes CSS and watches a div change color, they own that causality. The foundational approach lets me introduce complexity only after the underlying model is understood.
